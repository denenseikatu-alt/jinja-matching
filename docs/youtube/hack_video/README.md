# ハッキング被害を公式発表した企業と、その対応の動画（オーナー依頼 2026-10-30）

## 依頼の中身
- ハッカーによる攻撃を公式に発表した企業の名前と、企業の対応を紹介する動画。
- 裏付けは必ず企業の公式サイトで取る（検索結果の要約や第三者のまとめだけで書かない）。
- データ量の少ないスライド形式。スライドの絵は ChatGPT と Gemini の両方を適宜使う。
- 声は Gemini の「Leda」（オーナー指定）。
- X の投稿も、ChatGPT の絵を付けて用意する。
- 新しい種類の動画なので、まず限定公開で上げ、オーナーが見て良いと言ってから公開にする。

## 2026-10-30 時点で止まっていること（確かめた結果）
- 企業の公式サイト：通信制限で 403（kadokawa.co.jp、asahigroup-holdings.com、askul.co.jp など）。
- Gemini：前払いの残高切れ（402）。絵も声も作れない。
- ChatGPT：通信は通る（401 が返る）が、このセッションでは OPENAI_API_KEY が見えない。新しいセッションが必要。
- X：投稿の仕組みも鍵もない。api.x.com にもつながらない。ブラウザでのログインはしない。投稿文と絵を用意してオーナーが投稿する。

## 2026-10-30 午後の追記
- ChatGPT のキーは環境変数ではなく「ネットワークシークレット」（api.openai.com・Authorization: Bearer）で入っている。
  コードでキーを読む必要はなく、api.openai.com にそのまま送れば通信の途中でキーが付く。
  1回目は sk-proj- のキーが付いたが「Incorrect API key」。入れ替え後は「Missing bearer authentication」（キーが付かない）。新しいセッションで再確認する。
- つながった公式サイト：www.keio.co.jp・gmo-aozora.com・www.asahigroup-holdings.com・www.tein.co.jp（200）。
- www.nichirei.co.jp は通信制限で 403 のまま。jpn.nec.com はサイト側が curl を断る（403）。確認画面や断りはくぐり抜けない。

## 新しいセッションでの最初の手順
1. 上のドメインに curl でつながるか、OPENAI_API_KEY が読めるか、Gemini が 402 でないかを確かめる。
2. 各社の公式発表を自分で開いて読み、書いてあることだけで台本を作る（発表日・被害の内容・会社の対応）。
3. 限定公開で上げ、URL を YouTube から取り直してからオーナーに渡す。X の投稿文と絵も一緒に渡す。

## 2026-10-31 オーナーの判断（限定公開 uAU4QDZbDDc）
- 「情報が古すぎる」「声のアクセントがおかしすぎる」ため、オーナーが削除する。公開・X 投稿はしない。
- 反省：
  - 2025年の事案（アサヒ・テイン）や数か月前の発表まで入れた。作り直すなら、直近（目安1〜2か月以内）の発表に絞り、各社の最新の続報まで確かめる。
  - ChatGPT の声（gpt-4o-mini-tts・marin）は、文字起こしでは読みが合っていても、日本語のアクセントが不自然だった。文字起こしの一致はアクセントの確認にならない。日本語の読み上げに使う前に、短い見本をオーナーに聞いてもらい、アクセントの了承を取る。
