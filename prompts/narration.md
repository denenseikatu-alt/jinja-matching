# ナレーション台本ルール

`extract_article.py` が出力した `article.json` から、`build_video.py` に渡す
`script.json` を作るときの規約。

## 出力形式

```json
{
  "title": "動画タイトル",
  "source_url": "https://denenseikatu.com/column/.../",
  "speaker": 9,
  "scenes": [
    {
      "id": 1,
      "heading": "スライド見出し",
      "bullets": ["箇条書き（任意・最大4行）"],
      "lines": ["読み上げる文", "1文ずつ分ける"]
    }
  ]
}
```

- `speaker` は VOICEVOX の話者ID。既定は **9**（波音リツ / ノーマル）。
- `lines` の 1 要素 = 音声合成 1 回 = 字幕 1 枚。
- `bullets` は画面にだけ出る。読み上げは必ず `lines` に書く。

## 構成

1. **タイトルスライド**（`id: 1`）— 記事タイトルと、視聴者への呼びかけ 1〜2 文。
2. **本編** — 記事の `h2` を 1 スライド 1 見出しに対応させる。
   本文が長い節は 2 枚に割ってよい。
3. **結び** — 記事の締めを 1 枚。最後に出典サイト名を読み上げる。

**尺は記事の分量に合わせて決める（固定しない）。** 記事の要点を落とさず、水増しもしない。
目安は、読み上げ1,000字あたり約3分、スライド1枚あたり15〜40秒。

| 記事の本文（表を含む） | スライド | 尺の目安 |
| --- | --- | --- |
| 〜2,500字 | 6〜10枚 | 2〜5分 |
| 2,500〜5,000字 | 10〜16枚 | 5〜9分 |
| 5,000字〜 | 16〜20枚 | 9〜12分 |

スライドは最大20枚程度。短い記事を無理に引き延ばさない。

## 毎日の動画の形式（build_talking.py）

毎日の動画は、アニメ調のスーツ姿の語り手（`assets_video/presenter.png`）がセミナー室の
スクリーンの横に立ち、口を動かしながら話す形式。スクリーンに各シーンの `heading` と
`bullets` が映り、画面下に `lines` が字幕で出る。声は Gemini。

見本は `talk/40s-safe-aerobic-talking.json`。`speaker` の代わりに次を書く:

```json
"voice": {"engine": "gemini", "name": "Leda",
          "style": "Say in a bright, friendly young woman's voice, at a natural, lively conversational pace"},
```

- `style` は英語のまま変えない（日本語で書くと指示文まで読み上げる）。
- `youtube` に `"synthetic": true` を入れ、概要欄に「この動画の音声は、AI で生成したものです。」と書く。
- スクリーンは小さいので、`heading` は20字程度まで、`bullets` は1シーン4項目程度まで、
  1項目は25字程度までに収める。記事の表の数値は、`bullets` に「項目：数値」の形で載せる。
- `lines` は Gemini がそのまま読むので、自然な日本語で書く（VOICEVOX 用の読みの開きは不要）。
  英字の略語は読みやすい形のままでよい。

## 文章

- 記事の内容から逸脱しない。記事にない事実・数値・固有名詞を足さない。
- 書き言葉を話し言葉に直す。体言止めは避け、「〜です」「〜ます」で結ぶ。
- 1 文は 60 文字以内。超えるときは文を割る。
- 箇条書きを読み上げるときは「まず」「次に」「最後に」で順序を示す。
- 記事の注記（「※〜の場合もあります」など）は省略せず、必ずどこかで読む。

### 動画は聞き流される前提で書く

読者は戻って読み返せるが、視聴者はできない。

- **対比を扱う記事では、どちらの話をしているか毎文で示す。**
  「朝は〜、一方で夕方は〜」ではなく「朝の運動では〜です。夕方の運動では〜です」。
  主語を省くと、1文聞き逃しただけでどちらの話か分からなくなる。
- 前のスライドの内容を前提にしない。各スライドは単独で意味が通るようにする。
- 代名詞（これ、それ、この方法）を避け、対象を名前で言い直す。

## 数値とデータの扱い

- **記事にある数値だけを使う。** 概算・丸め・言い換えもしない。
  記事が「約12%」なら「約12パーセント」であって「1割ほど」ではない。
- 単位は読みを開く。`bullets` は記号のままでよい。

  | 表記 | `lines` での書き方 |
  | --- | --- |
  | kcal | キロカロリー |
  | % | パーセント |
  | kg / g | キログラム / グラム |
  | kg/m² | キログラム毎平方メートル |
  | 〜℃ | 〜度 |
  | 1.5倍 | いってんごばい |

- 数値が3つ以上並ぶ節は、読み上げでは2つまでに絞り、残りは `bullets` で見せる。
  耳で追える数は少ない。

## 研究・出典の扱い

研究結果を扱う記事では、**記事の主張の強さを変えないこと。** これは正確さの問題であり、
誇張は視聴者を誤らせる。

- 記事が「傾向がみられた」なら「傾向がみられました」。「証明された」「〜すべき」にしない。
- 記事が示している条件（被験者数、期間、対象者の属性）を落とさない。
  落とすと一般化しすぎになる。
- 大学名・研究機関名・研究者名は**記事の表記をそのまま使う**。略称に変えない。
- 記事が触れていない健康上の助言（「〜すると痩せます」など）を足さない。
- 出典が記事中に明示されていれば、結びで触れる。

## 読み間違い対策

VOICEVOX が誤読しやすい語は、`lines` の中で読みを開いて書く。
画面の `bullets` は漢字のままでよい。

`lines` は字幕にもなる。読みを開いた語を字幕では元の表記に戻したいときは、
台本の最上位に `"caption_replace": {"イーピーエー": "EPA"}` のように書く
（build_talking.py が字幕だけ置き換える。声は読みのまま）。英字の略語は必ずこうする。以下は神社記事で使った例。
**記事のジャンルに応じて作り直すこと。**

| 表記 | `lines` での書き方 |
| --- | --- |
| 正中 | せいちゅう |
| 柄杓 | ひしゃく |
| 手水 | てみず |
| 二礼二拍手一礼 | にれい、にはくしゅ、いちれい |
| 御神前・ご神前 | ごしんぜん |
| 産土神 | うぶすながみ |
| 狛犬 | こまいぬ |
| 注連縄 | しめなわ |

誤読しやすいのは、熟字訓、専門用語、固有名詞、そして**数字＋単位**。
迷ったら開いて書く。開きすぎて困ることはない。

- 読点「、」は息継ぎとして機能する。間を置きたいところに置く。
- 記号（※、›、｜）は読み上げに含めない。
- タイトルの「｜」以降の副題は、読み上げでは省いてよい。

## 免責

記事末尾の免責文（生成AI利用の旨など）は読み上げない。
`extract_article.py` が除外済み。診断ページへの導線も読み上げない。
